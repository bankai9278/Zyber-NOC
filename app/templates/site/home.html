// follow a ping

Follow one ping across the network.

Scroll to send a packet from this PC, through the home router, to a device and back. Every number on the way is something the app really measures.

  1. 01{{ icon("ping") }}

    Send an echo request

    This PC runs Windows ping -n 5: five ICMP echo requests (type 8), one after another. Each leaves with a TTL, a hop limit that Windows sets to 128.

  2. 02{{ icon("arrow") }}

    Pass through the router

    The home router forwards it toward the device and takes 1 off the TTL. If a TTL ever reaches 0, the packet is dropped instead of looping forever. Traceroute uses exactly that to find each hop.

  3. 03{{ icon("see") }}

    Get an echo reply

    The device answers with an echo reply (type 0). The time from request to reply is the latency. From five replies the app saves the median, plus jitter: the average change from one reply to the next.

  4. 04{{ icon("shield") }}

    Or hear nothing back

    Each request waits up to 1000 ms. Every one that times out counts as packet loss. All five lost means Offline, and a check that could not run is an Error. A device that was never checked stays Unknown, not Offline.

  5. 05{{ icon("store") }}

    Save it, then draw it

    The result goes into SQLite. A change of status is saved as its own event, and a drop to offline becomes an incident. Uptime, the 90-day bar, the latency chart and the topology are all drawn from those rows.
